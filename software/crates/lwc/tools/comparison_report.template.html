Per-image quality

Method

Requested filter: exclude images 0826 and 0861, where LWC exhausts its bit budget and loses substantial content near the frame bottom. All four codecs are scored on the same remaining ten images. The raw twelve-image measurements are retained separately. This subset describes quality when LWC avoids budget exhaustion, rather than its performance on an unfiltered sample.

Images come from the DIV2K validation HR set. A seeded shuffle (20261107) of the sorted archive filenames selects the first 12 originals at least 1280 pixels wide and 800 pixels tall, before any encoding. Originals are 2040 pixels wide and 1152–1536 pixels tall. Each is converted to 8-bit grayscale with Pillow’s RGB-to-L conversion (0.299 R + 0.587 G + 0.114 B), then center-cropped to 1280 × 800. No resize, denoise, sharpening, tiling, or per-codec preprocessing is applied.

All complete encoded files must fit in 128,000 bytes. LWC and JPEG XS produce exactly that size. JPEG and WebP use their actual complete file sizes; no padding is added to conceal rate underfill. PNG preview sizes are irrelevant to the rate calculation. LWC’s fixed frame includes zero padding; its mean semantic rate on these ten images is 0.774178 bpp. External network framing is excluded for every codec.

  • LWC: this workspace’s unmodified production Rust reference, v0.2.0, canonical 640-active/256-blank raster cadence, production burst limiting enabled. The fixed profile is not retuned. Its headerless dimensions and profile are known out of band.
  • JPEG: libjpeg-turbo 3.2.1, baseline grayscale, accurate integer DCT/IDCT and optimized Huffman coding. Search integer quality downward, then enumerate distinct scalar refinements of the standard luminance quantization table between the highest fitting quality and the next integer quality. Choose the lowest-error fitting trial. This refines table scale only, not table shape.
  • JPEG XS: official ISO/IEC 21122-5:2025 reference software, XSM 3.0.2-ED3, native one-component grayscale, 5 horizontal / 2 vertical decompositions, 16-line slices, High444.12 profile and fixed byte rate. The bundled tables do not include monochrome: use component-zero gains from its existing 3-component, no-color-transform PSNR table, with that component’s priorities rank-compressed. These fixed values are selected from source code, without image-specific fitting. Every stream is decoded by both XSM and SVT-JPEG-XS; all pixels match exactly. This measures one reference encoder configuration, not the best possible JPEG XS implementation.
  • WebP: libwebp 1.6.0 through Pillow 13.0.0, lossy method 6. Sixteen quality-bisection steps plus neighboring trials; choose the lowest-error fitting trial. WebP imports the gray image as equal RGB channels, uses normal internal color conversion, and includes all RIFF/chroma overhead. Decoded RGB is converted back to grayscale for measurement.

PSNR uses the complete frame, including boundaries, against the prepared grayscale source. Pooled PSNR is 10 log₁₀(255² / pooled MSE); mean PSNR is the arithmetic mean of the 10 per-image values. SSIM uses an 11 × 11 Gaussian window, σ = 1.5, population covariance, K₁ = 0.01, K₂ = 0.03, data range 255, and excludes a 5-pixel border. Higher PSNR and SSIM mean closer pixel reconstruction; neither proves preferred visual quality.

JPEG and WebP receive a full-image parameter search, while LWC and JPEG XS use fixed streaming-oriented configurations. This is a reconstruction-quality comparison, not a latency, hardware-area, power, or throughput benchmark. Ten retained native crops are a small subset, not the whole DIV2K set.

Exact JPEG XS configuration and reproduction 


From the repository, run bash software/crates/lwc/tools/reproduce_comparison.sh. Dependencies: Cargo, CMake, NASM, libjpeg-turbo cjpeg/djpeg, curl, unzip, and Python with Pillow, NumPy, SciPy, and Matplotlib. The script downloads the public reference software and sample images. See selection.json for original hashes and crop coordinates, metrics.json for measurements and search trials, and provenance.json for software hashes and versions.
